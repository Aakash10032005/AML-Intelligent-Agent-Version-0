# Anti-Money Laundering (AML) Intelligent Surveillance Engine v4.1

An autonomous, dynamic AI Agent system engineered with **LangGraph**, **LangChain**, **Google Gemini 2.5 Flash**, **Scikit-Learn**, **SQLite**, and **Streamlit** to detect, investigate, and report suspicious financial transaction patterns (such as Structuring/Smurfing and Layering) for Bank Secrecy Act (BSA) and Financial Crimes Enforcement Network (FinCEN) regulatory compliance.

---

## Executive Summary & Problem Statement

Financial institutions process billions of transactions daily, generating vast volumes of compliance alerts. Traditional Anti-Money Laundering (AML) surveillance systems rely heavily on rigid, static rule thresholds (e.g., flagging any single cash deposit over $10,000). These legacy frameworks present critical operational drawbacks:
1. **High False-Positive Rates**: Up to 90–95% of alerts generated by traditional rule-based systems are false positives, placing an immense operational burden on compliance teams.
2. **Evasion via Typology Manipulation**: Malicious actors easily bypass static rules by executing sub-threshold transactions (e.g., multiple transfers of $9,500 to evade Currency Transaction Reports) or using complex multi-account layering schemes.
3. **Rigid Execution Pipelines**: Conventional software pipelines execute fixed, monolithic analysis flows regardless of the investigator's specific query intent, causing high latency and compute inefficiencies.

### The Agentic Solution
This project introduces an **Autonomous Dynamic AML Surveillance Engine**. Driven by a stateful **LangGraph** state machine and powered by **Google Gemini**, the engine:
* **Parses Natural Language Directives**: Extracts intent, target typologies, date bounds, amount caps, and specific account IDs (e.g., `ACC_3127`).
* **Dynamically Constructs Execution Plans**: Determines the exact subset of analytical tools needed—invoking required modules while logging skipped nodes and explaining planner reasoning.
* **Integrates Hybrid Risk Scoring**: Combines Scikit-Learn `IsolationForest` ML anomaly detection with BSA regulatory rule-hits.
* **Automates FinCEN Incident Reporting**: Synthesizes findings into plain-English executive memorandums and exports structured FinCEN Suspicious Activity Report (SAR) JSON packages.
* **Provides Live Database & CSV Sync**: Features an interactive Streamlit dashboard backed by SQLite (`aml_transactions.db`) auto-synced with `transactions.csv`.

## Literature Survey & Theoretical Framework

### 1. Limitations of Legacy Rule-Based Compliance
Under the Bank Secrecy Act (BSA) (31 U.S.C. § 5311 et seq.) and FinCEN regulations (31 CFR § 1010.311), financial institutions must file a Currency Transaction Report (CTR) for any cash transaction exceeding $10,000. To prevent evasion, 31 U.S.C. § 5324 criminalizes **Structuring** (also known as *Smurfing*)—the deliberate breaking up of transactions into sub-threshold amounts. Legacy rule systems struggle to correlate multi-transaction velocity across time windows, failing to connect sub-threshold transactions without creating excessive false-alarm noise (FATF, 2021).

### 2. Machine Learning & Statistical Anomaly Detection
To move beyond rigid thresholding, modern AML frameworks adopt unsupervised anomaly detection algorithms. The **Isolation Forest** algorithm (Liu et al., 2008) explicitly isolates anomalies by randomly selecting a feature and splitting value, relying on the principle that suspicious financial profiles are few and quantitatively distinct. In our hybrid model:
$$\text{Hybrid Risk Score} = f(\text{Isolation Forest Anomaly Index}, \text{BSA Rule Hits}, \text{Behavioral Z-Score})$$
This dual approach ensures that statistical outliers (unusual transfer sizes or frequencies) and explicit regulatory rule violations (repeat sub-threshold CTR evasion) are captured in a unified risk spectrum.

### 3. Agentic AI & Dynamic Planning Systems
Recent breakthroughs in Large Language Model (LLM) orchestration frameworks (Yao et al., 2022; Wu et al., 2023) demonstrate that stateful LLM agents can perform multi-step planning, tool selection, and self-correction. By replacing static linear Directed Acyclic Graphs (DAGs) with dynamic stateful graphs (LangGraph), compliance software can evaluate natural language context, query specific database slices, and auto-draft regulatory documentation without human intervention until final approval.

## System Architecture & LangGraph Workflow

The core intelligence engine in [`agent.py`](file:///c:/AML-Intelligent-Agent-Version-0/agent.py) is structured as a stateful graph orchestrated by **LangGraph**.

```text
                        +------------------------------------+
                        |       User Natural Language        |
                        |      Directive / AML Query         |
                        +------------------------------------+
                                          |
                                          v
                        +------------------------------------+
                        |         parse_query_node           |
                        |       (Gemini 2.5 Flash)           |
                        |   Extracts Intent, Filters, Plan   |
                        +------------------------------------+
                                          |
                                          v
                        +------------------------------------+
                        |         route_after_parse          |
                        +------------------------------------+
                                 /                  \
        (Needs Clarification)   /                    \  (Valid Plan)
                               v                      v
                +----------------------------+  +----------------------------+
                |     clarification_node     |  |   execute_tools_pipeline   |
                |  (Human-in-the-Loop Exit)  |  |   (Dynamic Tool Routing)   |
                +----------------------------+  +----------------------------+
                                                            |
                        +-----------------------------------+-----------------------------------+
                        |                                   |                                   |
                        v                                   v                                   v
             [run_eda_tool]                   [feature_engineering_tool]             [detect_structuring_tool] /
             (Baseline EDA Statistics)        (Z-scores & Velocity Aggregations)     [detect_layering_tool]
                        |                                   |                                   |
                        +-----------------------------------+-----------------------------------+
                                                            |
                                                            v
                                               [risk_classification_tool]
                                              (Hybrid ML + Rule Scoring)
                                                            |
                                                            v
                                            +--------------------------------+
                                            |        explanation_node        |
                                            | (Generates Compliance Memo &   |
                                            |   FinCEN E-Filing SAR Package) |
                                            +--------------------------------+
```

### LangGraph State Definition (`AgentState`)
The agent maintains state across nodes via a structured `TypedDict`:
```python
class AgentState(TypedDict):
    user_query: str
    plan: dict
    invoked_tools: list[str]
    skipped_tools: list[str]
    needs_clarification: bool
    clarifying_question: str
    tool_outputs: list[str]
    final_explanation: str
    execution_summary: str
```

## Modular Tool Pipeline ([`tools.py`](file:///c:/AML-Intelligent-Agent-Version-0/tools.py))

The engine provides five specialized analytical tools decoratively wrapped with `@tool`:

| Tool Function | Core Responsibility | Input Parameters | Output Description |
| :--- | :--- | :--- | :--- |
| **`run_eda_tool`** | Exploratory Data Analysis | `query`, `date_start`, `date_end` | Total transaction counts, volume ($), average transaction size, ground-truth flags. |
| **`feature_engineering_tool`** | Feature extraction & deterministic rule filtering | `account_id`, `date_start`, `date_end`, `amount_min`, `amount_max`, `transaction_type`, `min_transaction_count` | Aggregates per-account velocity, structuring band hits ($9k–$9.99k), near-threshold ratios, and z-scores. |
| **`detect_structuring_tool`** | BSA Structuring / Smurfing pattern detection | `date_start`, `date_end` | Identifies accounts executing 3+ sub-threshold transfers ($9,000.00–$9,999.99) within short timeframes. |
| **`detect_layering_tool`** | Pass-through & fan-out transfer detection | `query`, `date_start`, `date_end` | Identifies rapid high-volume incoming transfers ($25k–$75k) split and transferred out instantly. |
| **`risk_classification_tool`** | Hybrid ML & BSA Rule Scoring Engine | `account_id`, `target_pattern`, `date_start`, `date_end` | Combines Scikit-Learn `IsolationForest` anomaly scores with rule hits (`HIGH`, `MEDIUM`, `LOW`). |

## Dataset Schema & Synthetic Generation ([`generate_data.py`](file:///c:/AML-Intelligent-Agent-Version-0/generate_data.py))

The system comes pre-loaded with 5,339 synthetic transaction records (`data/transactions.csv`), backed by SQLite (`aml_transactions.db`).

### Transaction Field Schema
* `account_id` (String): Unique identifier for the account (e.g., `ACC_1042`, `ACC_SMURF_9003`, `ACC_LAYER_8012`).
* `timestamp` (Datetime): ISO timestamp of transaction execution.
* `amount` (Float): Value in USD ($).
* `transaction_type` (String): Payment category (`PAYMENT`, `TRANSFER`).
* `is_suspicious` (Integer): Ground-truth binary flag (1 = Suspicious, 0 = Normal).
* `pattern_type` (String): Typology category (`Normal`, `Structuring`, `Layering`).

### Injected Typology Models
1. **Structuring (Smurfing)**: Malicious actors execute 4–6 rapid transfers just under the $10,000 CTR threshold (e.g., $9,000.00–$9,999.99) spaced 2 hours apart.
2. **Layering (Rapid Pass-Through)**: High-volume incoming transfers ($25,000–$75,000) rapidly split into 3–5 outbound transfers within 10-minute windows.

### 1. Prerequisites & Environment Setup
Ensure Python 3.10+ is installed on your system.

```bash

git clone https://github.com/Aakash10032005/AML-Intelligent-Agent-Version-0.git
cd AML-Intelligent-Agent-Version-0

# Create virtual environment
python -m venv aml_env

# Activate virtual environment
```

```bash
pip install streamlit pandas numpy scikit-learn langchain-google-genai langgraph python-dotenv
```
